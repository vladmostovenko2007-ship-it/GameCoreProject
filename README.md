# Дизайн-документ: Бізнес-логіка гри (Практичне заняття 14)

## 1. Архітектура проєкту
Проєкт побудований за принципом розділення відповідальності (шарів):
* **Шар представлення (Presentation):** Реалізовано через консоль (`Program.cs`).
* **Шар бізнес-логіки (Core):** Містить класи `Game`, `Character`, `CharacterProfile`, `Turn`. Відповідає за всі розрахунки та правила гри.
* **Шар інфраструктури/постійності (Data):** Реалізовано через `SaveGameService` (зберігає стан у JSON) та `CharacterApiService` (завантажує дані з API).

## 2. Каталог персонажів (Парсинг JSON)
Дані завантажуються з відкритого API (Genshin Impact API). Оскільки API може бути недоступним (помилка 521), реалізовано патерн "Заглушка" (Mock). Якщо сервер не відповідає, генеруються тестові персонажі з базовими характеристиками залежно від їхньої рідкості (Rarity).

## 3. Математика бою
Розрахунок шкоди відбувається за формулами:
* **Фізична атака:** `Шкода = (Атака - Броня ворога) * (1 - Резист ворога)`. Якщо показник після віднімання броні менший за 0, шкода дорівнює 0.
* **Магічна атака:** Ігнорує фізичну броню, але враховує відсоток резисту (опору магії).

## 4. Покрокова система (Turn System)
Система базується на накопиченні "Очок Дій" (Action Points).
* Кожен персонаж має характеристику `Speed` (Швидкість).
* На початку бою всі мають 100 очок.
* Одна дія (удар) коштує 100 очок.
* Після кожної дії персонажі відновлюють очки, що дорівнюють їхній швидкості. 
* Таким чином, персонаж зі швидкістю 200 діятиме вдвічі частіше, ніж персонаж зі швидкістю 100.

## 5. Збереження та завантаження (Save/Load)
Стан гри серіалізується у файл `savegame.json` за допомогою `System.Text.Json`. Зберігаються поточні характеристики персонажів (HP, рівень, інвентар), щоб гру можна було продовжити пізніше.
